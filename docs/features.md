# 功能规格

这一页写「功能应该怎么表现」，不写具体实现。目标是把边界讲清楚，换任何技术栈都能照着做。

## 一、目标设定与达成提醒

- 目标分两类：单次目标（本次跑 3 公里）与周期目标（本周 4 次、每周 15 公里）。
- 单次目标在开始训练前选择，训练中在界面上显示「还差多少」，不做打断式弹窗。
- 周期目标只在训练结束时判定，达成时给一次轻提示＋可选的语音播报，不重复弹。
- 目标未达成**不做惩罚性提示**。连续未达成时改成降级建议（例如把周目标从 4 次调成 3 次），而不是反复提醒。
- 所有目标以自然周 / 自然日为周期，与数据模型里的归日口径保持一致。

## 二、语音报数

播报的难点不是 TTS，而是「什么时候说、说什么、会不会烦」。

### 播报时机

- 按距离：每满 1 公里播一次（可配 0.5 / 1 / 2 公里）
- 按时间：每满 10 分钟播一次（可配）
- 阶段节点：即将达成目标时（例如还差 200 米）播一次
- 结束：训练结束后播总结，不受静音开关影响（由用户单独控制）

### 播报内容

短句，一句只放一个信息点，顺序固定：

```
已跑 3 公里，用时 21 分 40 秒，平均配速 7 分 13 秒每公里。
```

- 超过 3 个数字的句子要拆开，人听不清连读的三个以上数字
- 不播「干得漂亮」这类评价性内容，用户跑的时候不需要被夸
- 暂停与恢复各播一句短提示（例如「已暂停」「继续」），并说明计时不会丢

### 优先级

结束总结 > 目标达成 > 阶段节点 > 定时/定距播报。同时触发时只播最高优先级的一条，避免叠话。

### 避让

- 系统媒体正在播放时，采用「压低音量播报」而不是完全打断（ducking）
- 来电、导航播报进行中时，本轮播报直接跳过，不排队补播

## 三、周报

周报是一页能一次看完的东西，不要做成流水账。

结构建议（从上到下）：

1. 一句话结论：本周跑了 X 次、Y 公里，与上周相比的变化
2. 四个数字块：次数 / 里程 / 有效时长 / 平均每次时长
3. 一周柱状图：周一到周日，当天没跑留空而不是画 0，避免和「跑了 0 分钟」混淆
4. 最好的一次：哪天、多少公里、平均配速
5. 目标达成情况：周目标完成度（只出现在设了目标时）
6. 一句话建议：基于本周数据的一条，最多一条

反面清单：不要把每次训练的明细都列进去，不要放累计数据（累计属于「累计」页），不要用「继续加油」这种没有信息的句子。

## 四、累计跑步天数

- 展示两个数：累计天数、当前连续天数
- 连续天数在当天未跑时显示到昨天为止，并给出「今天还没记录」的状态，不提前清零
- 允许标记「休息日」：主动标记的休息日不打断连续天数，但一年内可标记的天数要有上限（例如 12 天），否则 streak 失去意义

## 五、历史记录与趋势图

- 列表页：按日分组，一天一组，组内按开始时间倒序；每条只显示时间、时长、里程、来源
- 详情页：时间轴（含暂停段）、分段配速、备注
- 趋势页：周粒度折线（里程 / 时长 / 平均配速三选一），可切换 30 天 / 12 周 / 全部
- 空状态要说明「还没有足够数据」而不是画一条平线
- 趋势页不给健康结论（例如「你的心肺能力提升了」），只呈现数据

## 六、暂停与恢复

- 暂停只停计时和距离累计，不结束本次记录
- 恢复后时间轴继续，`segments` 里新增一段 run
- 暂停期间不计入有效时长，但计入总时长展示（并标注）
- 屏幕锁定、切后台不应触发暂停，除非用户手动点
