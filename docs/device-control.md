# 设备遥控：现状与待验证项

**这一页只写「已经确认的事实」和「明确未验证的部分」**，不提供任何协议实现细节。不同厂商、不同批次的机器差异很大，套用别人的字节序和指令集是这类项目最常见的失败原因。

## 已确认

- 家用走步机 / 健步机常见两类遥控链路：蓝牙（BLE）与红外（IR）。
- 部分机型的控制协议在抓包中表现为短指令帧，需要按实际设备逆向，不能直接复用其他机型的帧格式。
- 手机侧做遥控，通常需要先与设备建立连接（BLE）或具备红外发射能力（部分机型需外接发射器）。
- 遥控能力与「运动数据上报」是两条独立链路：能遥控不代表能读数据，反过来也一样。

## 未验证 / 需要你自己实测

- 具体帧格式、校验方式、心率与速度数据所在的特征值 UUID。
- 是否需要握手、心跳、超时重连。
- 不同固件版本之间是否存在协议差异。
- 断电重启后是否需要重新配对。

## 抓包建议（通用方法，不含任何具体设备参数）

1. 用系统级蓝牙日志或第三方抓包工具记录官方 App 的完整会话，包括连接、订阅、下发指令三段。
2. 把「操作」和「字节流」一一对应起来记录：按一次加速键对应哪一段下发，同时观察上报有无变化。
3. 先从只读（订阅上报）入手，确认能解析速度/步数，再尝试下发控制指令。
4. 任何下发指令先在无人站在机器上的状态下验证，避免误触发速度变化造成伤害。

## 安全边界

- 不要在他人设备上做协议逆向。
- 不要绕过设备的安全锁、童锁或急停装置。
- 控制类指令必须有明确的停止/急停路径，软件层要保证松手即停。
